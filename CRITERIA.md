# Критерии оценки (зафиксированы ДО генерации)

> Дата фиксации: 2026-10-06. Этот документ написан **до** того, как запущена хоть одна
> генерация тестов. Менять критерии по ходу нельзя — это главное правило честного
> сравнения. Если появится критерий постфактум, он помечается как «добавлен после».

## Задача для всех подходов (одинаковая)

Сгенерировать набор автотестов (pytest) для учебной библиотеки `demo_project/ordercalc`
(3 модуля, 6 публичных функций). Код под тест — чистый Python без внешних зависимостей,
с большим количеством краевых случаев (граничные значения, округление half-up,
распределение остатка, високосные годы, валидация входов).

## Сравниваемые подходы (лестница)

| Уровень | Подход | Что это |
|---|---|---|
| L0 | Чат | Ручной copy-paste кода в чат с LLM, ответ копируем обратно в файл |
| L1 | Прямой API | Один вызов LLM API из скрипта, без инструментов и итераций |
| L2 | Простой харнесс | Свой мини-агентный цикл: модель + 1–2 инструмента (запуск тестов), ≤3 итераций |
| L3 | Топовый харнесс | Полноценный агент с файловыми инструментами, bash, правкой кода, само-проверкой |
| L4 | MCP + мультиагент | Конвейер из специализированных агентов (аналитик → писатель → критик) + MCP-инструменты |
| REF | Эталон (человек) | Тесты, написанные опытным разработчиком вручную — верхняя планка качества |

Ось «модели» (сравнение на уровне L1): малая/локальная модель ↔ средняя ↔ топовая.
См. `SETUP.md` за списком моделей и как их подключить.

## Метрики (все считаются автоматически, `evaluation/evaluate.py`)

### Качество (0–100)

| # | Метрика | Как считаем | Зачем |
|---|---|---|---|
| Q1 | Запускаемость | `pytest --collect-only` без ошибок (0/1) | Тесты, которые не собираются, не стоят ничего |
| Q2 | Прохождение на эталоне | % прошедших тестов на чистом коде | Тесты не должны падать на правильном коде |
| Q3 | Покрытие (line) | `coverage.py`, % строк `ordercalc` на чистом коде | Полнота проверки логики |
| Q4 | Покрытие (branch) | `coverage.py --branch`, % веток | Краевые условия, а не «счастливый путь» |
| Q5 | Чувствительность к багам | % пойманных багов из 5 заранее посеянных (тест-сьют прогоняется против каждого баг-варианта; баг «пойман», если упал ≥1 тест) | Главная метрика: тесты должны ловить регрессии |

Баги (посеяны в `demo_project/variants/`, детали вскрыты после оценки в `results/`):
5 независимых дефектов — порог off-by-one, банковское округление вместо half-up,
потеря остатка при дележе суммы, порог множителя баллов, срок жизни баллов −1 день.

### Экономика

| # | Метрика | Как считаем |
|---|---|---|
| E1 | Входные токены | Точный промпт/контекст, посланный модели; при API — из `usage` ответа; при сессионных прогонах — считаем отправленные тексты |
| E2 | Выходные токены | Все сгенерированные тексты/артефакты (включая промежуточные ответы в циклах) |
| E3 | Стоимость, $ | E1/E2 × прайс модели (цены в `evaluation/prices.py`, ориентировочные, с датой) |
| E4 | Время | Wall-clock от старта генерации до финального артефакта |

**Протокол подсчёта токенов:** если доступен `tiktoken` — считаем им (cl100k_base,
близкая оценка для большинства моделей); иначе оценка `символы / 4` (стандартная
эвристика для кода на английском). Способ помечается в `results/results.json`.

### Объём (справочно)

| # | Метрика |
|---|---|
| V1 | Число тест-функций |
| V2 | Число assert'ов |

## Правила честного сравнения

1. Все подходы получают **один и тот же базовый промпт** задачи (`levels/level1_api/prompts/task.md`); отличаться может только обвязка (чат-обёртка, инструменты, роли агентов).
2. Модель — одна и та же для сравнения подходов (GLM-5.3). Сравнение моделей — отдельная ось на уровне L1.
3. Критик/агентам запрещено подглядывать в баг-варианты и в эталонные тесты REF.
4. Одна попытка на подход (N=1): это демо-эксперимент, а не статистика; волатильность обсуждается в отчёте отдельно.
5. Прогоны, выполненные в сессии ZCode (без внешнего API-ключа), помечаются
   `executor: "session-subagent"` — цифры токенов по протоколу выше, полная
   воспроизводимость через скрипты уровней с вашим ключом.

## Формула итогового балла (для рейтинга в таблицах)

```
Score = 0.30*Q5 + 0.20*Q3 + 0.10*Q4 + 0.20*Q2 + 0.20*(экономика)
экономика = нормированная дешевизна (чем меньше E1+E2, тем выше)
```
Score — иллюстративный, для сортировки в презентации; все исходные метрики публикуются рядом.
