# Уровень L1. Прямой вызов LLM API — «модель как функция»

Убираем человека из цикла: скрипт сам собирает промпт, сам вызывает API, сам
сохраняет результат и **точно** измеряет токены (поле `usage` в ответе API).

## Как сделать

1. Получите ключ любого OpenAI-совместимого провайдера — см. `SETUP.md`, раздел 2
   (Z.AI / OpenRouter / OpenAI; для локальных моделей — Ollama, раздел 3).
2. Экспортируйте переменные и запустите:
   ```bash
   export LLM_API_KEY=sk-... LLM_BASE_URL=https://api.z.ai/api/paas/v4 LLM_MODEL=glm-4.6
   python levels/level1_api/direct_api.py --out results/runs/l1_api_glm46
   ```
3. Прогоните оценку: `python evaluation/evaluate.py results/runs/l1_api_glm46`.
4. Поменяйте `LLM_MODEL` и повторите — вот и сравнение моделей одной командой:
   ```bash
   LLM_MODEL=glm-4.6-flash python ... --out results/runs/l1_api_flash
   LLM_BASE_URL=http://localhost:11434/v1 LLM_MODEL=qwen2.5-coder:7b python ... --out results/runs/l1_api_local
   ```

## Что важно понимать

- **Промпт = функция от кода**: `compose_prompt()` вклеивает исходники в текст.
  Изменился код — промпт пересоберётся сам. В чате (L0) этим занимались вы.
- **Ответ ненадёжен**: модель может обернуть код в ```или добавить болтовню —
  `extract_code()` это чистит, но в общем случае нужна валидация ответа.
- **Одна попытка**: модель не видит результат запуска тестов. Ошиблась — и это
  финал. Обратную связь даёт следующий уровень (L2).
- **usage точен**: API сам сообщает `prompt_tokens` / `completion_tokens` —
  это единственный уровень, где экономия токенов измеряется идеально точно.

## Плюсы

- Воспроизводимо, автоматизируемо, CI-ready.
- Точный учёт токенов и стоимости → осознанный выбор модели.
- Дёшево: один запрос, минимум кода (~100 строк).
- Универсально: один протокол на все провайдеров, включая локальные.

## Минусы

- **Слепая генерация**: качество целиком зависит от модели и промпта.
- Нет доступа к вашему проекту (только то, что вклеено в промпт).
- Ограничение длины: большой код в промпт не вклеишь (здесь 1.8k токенов — легко).
- Парсинг ответа — зона хрупкости.

## Когда использовать

Массовые однотипные задачи (генерация тестов/докстрингов/ченджлога по шаблону),
сравнение моделей, дешёвый первый проход перед дорогим агентом.
