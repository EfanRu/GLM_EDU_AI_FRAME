# Уровень L2. Простой харнесс — «агент из подручных средств»

Харнесс (англ. harness — «упряжь») — это обвязка вокруг модели, которая даёт ей
**инструменты** и **цикл обратной связи**. Наш мини-харнесс ~200 строк
(`mini_agent.py`): модель пишет тесты → просит запустить → видит падения pytest →
исправляет. Один инструмент, жёсткий лимит итераций.

## Как устроен цикл

```
пользовательская задача + код
        │
        ▼
┌──► LLM отвечает: «```python ...``` + RUN_TESTS»
│       │
│       ▼
│   харнесс: сохранить блок в test_ordercalc.py
│       │
│       ▼
│   харнесс: песочница (копия ordercalc + тест) → pytest → вывод модели
│       │
└───────┘  (≤ 3 итераций, потом финальный код)
```

Протокол диалога — текстовый (`RUN_TESTS`), поэтому работает с **любым**
OpenAI-совместимым API, включая локальный Ollama, без поддержки function calling.

## Как сделать

```bash
export LLM_API_KEY=... LLM_BASE_URL=... LLM_MODEL=glm-4.6
python levels/level2_simple_harness/mini_agent.py --out results/runs/l2_mini_glm46
python evaluation/evaluate.py results/runs/l2_mini_glm46
```

## Что меняется по сравнению с L1

- Модель **видит результат своих действий** — типичные ошибки (опечатка в импорте,
  неверное ожидание) исправляются в цикле, а не остаются в файле.
- Токенов больше: каждый круг заново отправляется вся история диалога.
  Именно здесь впервые видна экономика «качество ↔ токены».

## Плюсы

- Качество заметно выше при той же модели — за счёт самопроверки.
- Полный контроль: свой код, свой протокол, свои лимиты — ничего магического.
- Дёшево в поддержке: один файл, ноль зависимостей кроме `requests`.
- Отличный учебный шаг: так устроены все агентные фреймворки «под капотом».

## Минусы

- Хрупкий текстовый протокол (модель может забыть слово RUN_TESTS).
- Один инструмент — один класс задач; для новых инструментов переписывать код.
- Контекст растёт линейно с итерациями, менеджмента нет.
- Модель не читает ваш проект сама — вы всё ещё вклеиваете код в промпт.

## Когда использовать

Когда задача повторяемая, но не заслуживает полноценного агента; когда нужен
полный контроль над расходами; когда надо понять агентные механизмы изнутри.
