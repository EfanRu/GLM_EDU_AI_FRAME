# Баг-варианты (спойлер к критериям!)

> В этом файле — ответы «экзамена». Не показывайте генерирующим агентам.
> В презентации вскрывается после таблиц с результатами.

| Вариант | Модуль | Баг | Пример входа, ломающего поведение |
|---|---|---|---|
| bug1 | discounts | `bulk_discount_percent`: граница `qty >= 100` заменена на `qty > 100` | `bulk_discount_percent(100)` → 7 вместо 12 |
| bug2 | discounts | `apply_tier_discount`: банковское `round()` вместо half-up | `apply_tier_discount(310, "silver")` → 294 вместо 295 |
| bug3 | split | `split_payment`: остаток не раздаётся, сумма частей < суммы | `split_payment(105, 2)` → [52, 52] вместо [53, 52] |
| bug4 | loyalty | порог x3: `>= 500000` заменён на `> 500000` | `points_for_order(10000, 500000)` → 200 вместо 300 |
| bug5 | loyalty | срок жизни баллов 364 дня вместо 365 | балл, начисленный 2024-02-29, проверка на 2025-02-28 → 0 вместо исходного |

Механика проверки: `evaluation/evaluate.py` копирует чистый пакет `ordercalc`,
подменяет один файл вариантом и запускает тест-сьют. Баг «пойман», если упал
хотя бы один тест. Проверка ловит ровно одну регрессию на вариант — остальные
функции не тронуты.
